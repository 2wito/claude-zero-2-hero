# ספריית תבניות: סוכנים, פקודות ו-Skills מוכנים

בפרקים 11 ו-12 למדנו לבנות Skills וסוכנים בעצמנו. אבל לא תמיד צריך להתחיל מאפס: הקהילה כבר כתבה מאות כאלה. הפרק הזה הוא **ספרייה מסוננת**, עם הפריטים השימושיים ביותר מתוך [aitmpl.com](https://www.aitmpl.com/), הקטלוג של הפרויקט הפתוח [Claude Code Templates](https://github.com/davila7/claude-code-templates) (רישיון MIT).

לכל פריט יש **הסבר בעברית** מה הוא עושה ומתי להשתמש בו, **פקודת התקנה** להעתקה, **בקשה מוכנה** להפעלה, ו**דוגמה לתוצאה**.

<Callout type="note" title="איך להשתמש בפרק הזה">
- **לא צריך להתקין הכול.** התחילו מ-2 או 3 פריטים שפותרים בעיה שיש לכם עכשיו.
- **השתמשו בכפתורי הסינון** כדי לראות רק סוכנים, רק פקודות, רק Skills או רק כלי עזר.
- **הדוגמאות לתוצאה הן להמחשה.** הקבצים בקטלוג נכתבים ומתעדכנים על ידי הקהילה, ולכן התוצאה אצלכם יכולה להיראות קצת אחרת.
</Callout>

## לפני שמתחילים

### מה צריך

- **Node.js** (פרק 6), כי ההתקנה רצה עם `npx`.
- **פרויקט עם Git**, כדי שתוכלו לראות בדיוק אילו קבצים ההתקנה הוסיפה, ולבטל בקלות.
- להריץ את פקודות ההתקנה **מתוך תיקיית הפרויקט**.

### איך ההתקנה עובדת

לכל סוג רכיב יש דגל משלו:

```bash title="המבנה הכללי"
npx claude-code-templates@latest --agent   <קטגוריה>/<שם>  --yes
npx claude-code-templates@latest --command <קטגוריה>/<שם>  --yes
```

`--yes` מדלג על שאלות האישור. ובלי שום דגל, מקבלים מסך בחירה אינטראקטיבי:

```bash title="מסך בחירה אינטראקטיבי"
npx claude-code-templates@latest
```

<Callout type="warning" title="אחרי כל התקנה: לבדוק מה נכנס">
כל רכיב מהקטלוג הוא **הוראות ש-Claude יבצע**, ולפעמים גם הרשאות לכלים. אחרי התקנה:

1. הריצו `git status` כדי לראות אילו קבצים נוספו. בדרך כלל הם בתוך התיקייה `.claude`.
2. **קראו את הקבצים**, או בקשו מ-Claude לעשות את זה בשבילכם (הבקשה מיד למטה).
3. בסוכנים, בדקו את השדה `tools`. סוכן "סוקר" שמבקש הרשאות כתיבה מלאות צריך להדליק נורה אדומה.
4. לא מתאים? `git restore` ו-`git clean` מחזירים את המצב, או פשוט מוחקים את הקובץ.
</Callout>

<Prompt>הרגע התקנתי רכיבים מ-claude-code-templates. תריץ git status, תקרא כל קובץ חדש בתיקייה .claude, ותסביר לי בעברית מה כל אחד עושה, לאילו כלים הוא מקבל גישה, ואם יש בו משהו חשוד או מיותר. אל תפעיל אף אחד מהם</Prompt>

```markdown title=".claude/skills/refactor-safely/SKILL.md"
---
name: refactor-safely
description: Safely refactor a file or module without changing behavior. Use when the user asks to clean up, simplify, split, or restructure existing code.
argument-hint: [file-path]
---

Refactor $0 without changing any user-visible behavior.

1. Read $0 and list the problems (long functions, duplication, unclear names).
2. If there are no tests covering $0, write minimal tests that lock in
   current behavior FIRST, and run them.
3. Propose a plan of small steps. WAIT for approval.
4. Apply one step at a time. After each step run the tests and `npm run build`.
   If anything fails, revert that step and explain why.
5. Finish with a Hebrew summary: what changed, what did not, and why it is safer.
```
