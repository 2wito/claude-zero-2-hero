# השיחה הראשונה והפקודות הבסיסיות

Claude Code מותקן ומחובר. עכשיו מגיע החלק הכיפי: בפרק הזה תפעילו אותו בפעם הראשונה, תבקשו ממנו לבנות דף אינטרנט קטן, ותלמדו לאשר את הפעולות שלו בבטחה.

<Callout type="note" title="מה נעשה בפרק">
1. ניצור תיקיית תרגול ונפעיל בה את Claude Code.
2. נשאל שאלה ראשונה ונבקש משימה ראשונה.
3. נלמד לקרוא בקשות אישור (הרשאות) ולהחליט מתי לאשר.
4. נכיר את הפקודות הבסיסיות: `/help`, `/clear`, `/compact` ו-`/exit`.
</Callout>

## שלב 1: יוצרים תיקיית פרויקט ונכנסים אליה

Claude Code עובד **בתוך תיקייה**. כל מה שהוא קורא ומשנה נמצא בתיקייה שבה הפעלתם אותו. לכן ההרגל הראשון: **תמיד נכנסים לתיקיית הפרויקט לפני שמפעילים את `claude`**.

שלוש פקודות טרמינל שכדאי להכיר:

| פקודה | מה היא עושה | דוגמה |
| --- | --- | --- |
| `mkdir` | יוצרת תיקייה חדשה | `mkdir my-project` |
| `cd` | נכנסת לתיקייה | `cd my-project` |
| `cd ..` | יוצאת לתיקייה שמעל | `cd ..` |

נפתח טרמינל וניצור תיקיית תרגול. הפקודות זהות בכל מערכות ההפעלה:

<Tabs groupId="os" items={["Windows PowerShell", "Windows CMD", "macOS / Linux"]}>
<Tab>

```powershell title="Windows PowerShell"
cd ~\Desktop
mkdir my-project
cd my-project
```

</Tab>
<Tab>

```bat title="Windows CMD"
cd %USERPROFILE%\Desktop
mkdir my-project
cd my-project
```

</Tab>
<Tab>

```bash title="macOS / Linux"
cd ~/Desktop
mkdir my-project
cd my-project
```

</Tab>
</Tabs>

השורה הראשונה עוברת לשולחן העבודה, השנייה יוצרת שם תיקייה בשם `my-project`, והשלישית נכנסת אליה. תוכלו לראות את התיקייה החדשה על שולחן העבודה.

<Callout type="tip" title="טריק שחוסך הקלדה">
התחילו להקליד שם של תיקייה ולחצו **Tab**: הטרמינל ישלים את השם לבד. זה עובד בכל מערכות ההפעלה.
</Callout>

## שלב 2: מפעילים את Claude Code

כשאתם בתוך התיקייה, הקלידו:

```bash title="בכל מערכת הפעלה"
claude
```

בפעם הראשונה בכל תיקייה, Claude Code ישאל אם אתם **סומכים על הקבצים בתיקייה**. זו תיקייה שיצרתם עכשיו, אז אפשר לאשר.

<Callout type="warning" title="למה הוא שואל?">
פרויקטים יכולים להכיל הגדרות שמשפיעות על מה ש-Claude Code עושה. אם הורדתם פרויקט ממקור שאתם לא מכירים, עדיף לא לאשר עד שתבינו מה יש בו. לתיקיות שלכם זה תמיד בסדר.
</Callout>

עכשיו מופיע מסך הפתיחה. מעל שורת הכתיבה רואים את **הגרסה**, את **המודל** (איזה Claude עובד איתכם) ואת **התיקייה** שבה הוא עובד. בדקו שזו התיקייה הנכונה.

## שלב 3: השאלה הראשונה

כותבים ל-Claude כמו שכותבים לחבר, ואפשר בעברית. נתחיל בשאלה פשוטה:

<Prompt>מה יש בתיקייה הזאת?</Prompt>

כיוון שהתיקייה ריקה, הוא יגיד לכם שאין בה כלום. עכשיו ננסה משהו מעניין יותר, משימה אמיתית:

<Prompt>צור דף אינטרנט בקובץ index.html עם ברכת יום הולדת לסבתא. עיצוב צבעוני ושמח, עם כותרת גדולה וכפתור שמפעיל קונפטי</Prompt>

Claude יתכנן מה לעשות, ואז, תלוי במצב ההרשאות (נסביר עוד רגע), יבקש את אישורכם ליצור את הקובץ. אשרו, ואז פתחו את הקובץ `index.html` מהתיקייה בדפדפן (לחיצה כפולה). יש לכם דף אינטרנט!

<Callout type="tip" title="ממשיכים לשפר">
זו שיחה, אז אפשר להמשיך לבקש שינויים: "תגדיל את הכותרת", "תוסיף תמונה של עוגה", "תכתוב את הברכה בחרוזים". Claude זוכר את כל מה שנאמר בשיחה, ולא צריך להסביר הכול מחדש.
</Callout>

## שלב 4: מבינים את בקשות האישור (הרשאות)

זה החלק החשוב ביותר בפרק. Claude Code יכול לבצע שלושה סוגים של פעולות, ולכל אחד רמת סיכון אחרת:

| סוג פעולה | דוגמה | רמת סיכון |
| --- | --- | --- |
| **קריאה** | לפתוח קובץ, לחפש בפרויקט | נמוכה: שום דבר לא משתנה |
| **עריכת קבצים** | ליצור קובץ, לשנות שורה | בינונית: אפשר להחזיר אחורה |
| **הרצת פקודות** | להתקין תוכנה, להריץ סקריפט, למחוק | הכי גבוהה: פקודה יכולה לעשות כמעט הכול |

כש-Claude רוצה לבצע פעולה שדורשת אישור, הוא עוצר ומציג **בקשת אישור** עם בדיוק מה הוא מתכוון לעשות. בדרך כלל יש שלוש אפשרויות:

1. **Yes** (כן): לאשר את הפעולה הזאת.
2. **Yes, and don't ask again** (כן, ואל תשאל שוב): לאשר, ולא לשאול שוב על פעולות דומות. הנוסח המדויק משתנה לפי סוג הפעולה.
3. **No** (לא): לסרב, ואפשר גם להסביר ל-Claude מה לעשות אחרת. הוא ימשיך לפי ההסבר שלכם.

### איך מחליטים אם לאשר?

**בעריכת קובץ**, Claude מציג את השינוי: שורות שנמחקות מסומנות באדום, ושורות שנוספות בירוק. שאלו את עצמכם:

- זה הקובץ שציפיתי שישתנה?
- השינוי קשור למה שביקשתי?

**בהרצת פקודה**, קראו את הפקודה עצמה. רוב הפקודות תמימות לגמרי: הרצת האתר, התקנת חבילה שביקשתם, בדיקה. אבל יש כמה דגלים אדומים:

<Callout type="warning" title="עצרו וחשבו לפני שאתם מאשרים פקודה עם">
- **`rm`, `del` או `Remove-Item`**: מחיקת קבצים. בדקו בדיוק **מה** נמחק.
- **`sudo`**: הרצה בהרשאות מנהל של כל המחשב.
- **`curl ... | bash`** או **`irm ... | iex`** מכתובת שאתם לא מכירים: הורדה והרצה של קוד מהאינטרנט.
- **`git push`**: העלאת קוד לאינטרנט, למשל ל-GitHub.
- **נתיבים מחוץ לתיקיית הפרויקט**, למשל תיקיית המסמכים או תיקיות מערכת.
- **סיסמאות או מפתחות** שמופיעים בתוך הפקודה.

לא בטוחים? בחרו **No** ושאלו: "תסביר לי מה הפקודה הזאת עושה לפני שאני מאשר". זו שאלה לגיטימית לגמרי, והוא יסביר בשמחה.
</Callout>

### מצבי הרשאות: כמה חופש לתת ל-Claude

Claude Code עובד באחד מכמה **מצבי הרשאות**. המצב הנוכחי מופיע בשורת המצב בתחתית המסך. כדי לעבור בין המצבים לוחצים **`Shift + Tab`**:

| מצב | מה מופיע בשורת המצב | מה קורה |
| --- | --- | --- |
| **ידני** (Manual) | `manual mode on` | Claude רק קורא בחופשיות, ושואל לפני כל עריכה ולפני כל פקודה |
| **אישור עריכות** (Accept edits) | `accept edits on` | עורך קבצים בלי לשאול, אבל שואל לפני רוב הפקודות |
| **תכנון** (Plan) | `plan mode on` | רק קורא ומתכנן, ולא משנה כלום עד שתאשרו את התוכנית |
| **אוטומטי** (Auto) | `auto mode on` | עובד בלי לשאול, ומודל בטיחות נפרד בודק כל פעולה ברקע וחוסם פעולות מסוכנות |

<Callout type="info" title="באיזה מצב Claude Code מתחיל?">
בגרסאות החדשות, Claude Code מתחיל בדרך כלל ב**מצב אוטומטי**: הוא עובד בלי לעצור לשאלות, ומנגנון בטיחות מובנה בודק כל פעולה. זה נוח מאוד, אבל בזמן הלמידה עדיף **לראות** כל צעד שלו.
</Callout>

<Callout type="tip" title="ההמלצה שלנו למתחילים">
בשבועות הראשונים לחצו `Shift + Tab` עד ששורת המצב מראה **manual mode on**. כך תראו כל קובץ שמשתנה וכל פקודה שרצה, ותבינו איך Claude עובד. כשתרגישו בנוח, עברו ל-**accept edits** או ל-**auto**.
</Callout>

### טעיתם? אפשר לחזור אחורה

- **`Esc`** (לחיצה אחת): עוצר את Claude באמצע פעולה. אחר כך אפשר להגיד לו מה לעשות אחרת.
- **`Esc` פעמיים**, או הפקודה **`/rewind`**: פותח תפריט של נקודות קודמות בשיחה. אפשר להחזיר את השיחה, את הקבצים או את שניהם למצב שהיה.

<Callout type="warning" title="מה החזרה אחורה לא מבטלת">
`/rewind` מחזיר שינויים שClaude עשה **בעריכת קבצים**. פעולות שקרו דרך **פקודות בטרמינל**, כמו מחיקה, התקנה או העלאה לאינטרנט, לא תמיד אפשר לבטל. זו עוד סיבה לקרוא פקודות לפני שמאשרים. בפרק 8 נלמד להשתמש ב-Git כרשת ביטחון חזקה יותר.
</Callout>

## שלב 5: הפקודות הבסיסיות

בתוך Claude Code, כל מה שמתחיל ב-**`/`** (סלאש) הוא **פקודה** ל-Claude Code עצמו, ולא הודעה ל-Claude. הקלידו `/` לבד כדי לראות רשימה של כל הפקודות.

### `/help`: עזרה

מציג את הפקודות הזמינות והסבר קצר על כל אחת. בכל פעם שאתם לא בטוחים, תתחילו מכאן.

```text title="בתוך Claude Code"
/help
```

### `/clear`: מתחילים שיחה חדשה

מוחק את השיחה הנוכחית מהזיכרון של Claude ומתחיל דף חלק. **הקבצים לא נמחקים**, רק השיחה.

```text title="בתוך Claude Code"
/clear
```

**מתי להשתמש:** כשעוברים למשימה חדשה שלא קשורה לקודמת. למשל, סיימתם עם דף יום ההולדת ועכשיו רוצים לעבוד על משהו אחר.

<Callout type="note" title="השיחה הקודמת לא הולכת לאיבוד">
גם אחרי `/clear` אפשר לחזור לשיחה קודמת עם `/resume`, שמציג רשימה של שיחות קודמות לבחירה.
</Callout>

### `/compact`: מפנים מקום בזיכרון

כדי להבין את הפקודה הזאת צריך להכיר מושג אחד: **חלון ההקשר** (Context Window).

תחשבו על לוח מחיקה. כל מה שנאמר בשיחה, כל קובץ ש-Claude קרא וכל תוצאה של פקודה נכתבים על הלוח. ככה Claude "זוכר" מה קורה. אבל ללוח יש גודל מוגבל, ובשיחה ארוכה הוא מתמלא.

`/compact` **מסכם** את השיחה עד עכשיו: מוחק את הלוח ורושם עליו סיכום קצר של הדברים החשובים. ממשיכים באותה משימה, אבל עם הרבה מקום פנוי.

```text title="בתוך Claude Code"
/compact
```

אפשר גם להגיד ל-Claude **על מה לשים דגש** בסיכום:

```text title="בתוך Claude Code"
/compact תשמור את רשימת השינויים שעשינו בעיצוב ואת מה שנשאר לעשות
```

| | `/clear` | `/compact` |
| --- | --- | --- |
| מה קורה לשיחה | נמחקת, ומתחילים מאפס | מסוכמת, וממשיכים מאותה נקודה |
| מתי להשתמש | משימה חדשה ולא קשורה | אותה משימה, אבל השיחה ארוכה מאוד |

<Callout type="tip" title="איך יודעים שהלוח מתמלא?">
הקלידו `/context` כדי לראות כמה מחלון ההקשר כבר בשימוש. כשהוא מתקרב לסוף, Claude Code גם **מסכם אוטומטית** בעצמו. אבל אם אתם באמצע משימה ארוכה, עדיף להריץ `/compact` בעצמכם בנקודת עצירה טבעית, למשל אחרי שסיימתם חלק מהעבודה.
</Callout>

### `/exit`: יציאה

סוגר את Claude Code ומחזיר אתכם לטרמינל הרגיל.

```text title="בתוך Claude Code"
/exit
```

אפשר גם ללחוץ **`Ctrl + D` פעמיים** ברצף.

### עוד פקודות שימושיות

| פקודה | מה היא עושה |
| --- | --- |
| `/context` | מראה כמה מחלון ההקשר בשימוש |
| `/resume` | חוזרים לשיחה קודמת מתוך רשימה |
| `/rewind` | חוזרים לנקודה קודמת בשיחה ובקבצים |
| `/usage` | מראה את השימוש והעלות, ואת מגבלות המנוי |
| `/status` | מראה גרסה, מודל וחשבון מחובר |
| `/model` | מחליפים את המודל של Claude |

### קיצורי מקלדת

| קיצור | מה הוא עושה |
| --- | --- |
| `Esc` | עוצר את Claude באמצע פעולה |
| `Esc` פעמיים | פותח את תפריט החזרה אחורה |
| `Shift + Tab` | מחליף מצב הרשאות |
| `↑` (חץ למעלה) | מחזיר הודעות קודמות שכתבתם |
| `@` | מזכירים קובץ ספציפי, למשל `@index.html` |
| `!` בתחילת השורה | מריצים פקודת טרמינל ישירות, בלי לעבור דרך Claude |
| `Ctrl + C` | עוצר פעולה, או מנקה את השורה. פעמיים ברצף יוצאים |

## מתחילים מהטרמינל: קיצורי דרך שימושיים

את הפקודות האלה מקלידים בטרמינל הרגיל, **לפני** שנכנסים ל-Claude Code:

```bash title="בטרמינל"
# מפעיל את Claude Code עם משימה מוכנה
claude "תוסיף לדף כפתור שמשמיע מוזיקה"

# ממשיך את השיחה האחרונה בתיקייה הזאת
claude -c

# בוחרים שיחה קודמת מתוך רשימה
claude -r
```

## תרגיל: הפרויקט הראשון שלכם

הגיע הזמן לעבוד לבד. בתיקיית `my-project`:

1. עברו למצב **manual** עם `Shift + Tab`.
2. בקשו מ-Claude להוסיף לדף יום ההולדת **גלריית תמונות** (אפשר תמונות לדוגמה מהאינטרנט).
3. קראו כל בקשת אישור לפני שאתם מאשרים. שימו לב לאילו קבצים הוא נוגע.
4. בקשו שינוי עיצוב כלשהו, ובבקשת האישור בחרו **No** והסבירו לו לעשות משהו אחר.
5. נסו `Esc` פעמיים וחזרו לגרסה הקודמת של הדף.
6. הריצו `/context`, ואז `/compact`, וראו כמה מקום התפנה.
7. צאו עם `/exit`, וחזרו לשיחה עם `claude -c`.

<Callout type="tip" title="הצלחתם?">
כל הכבוד! עכשיו אתם יודעים להפעיל את Claude Code, לבקש ממנו משימות, לאשר פעולות בבטחה ולנהל את השיחה. אלה היסודות שכל השאר בנוי עליהם.
</Callout>

## סיכום

- תמיד נכנסים לתיקיית הפרויקט (`cd`) לפני שמפעילים את `claude`.
- כותבים ל-Claude בשפה רגילה, וממשיכים לשפר בשיחה.
- **קוראים בקשות אישור** לפני שמאשרים, ובמיוחד פקודות שמוחקות, מעלות לאינטרנט או נוגעות מחוץ לפרויקט.
- `Shift + Tab` מחליף מצבי הרשאות, ולמתחילים מומלץ להתחיל ב-manual.
- `/help` לעזרה, `/clear` לשיחה חדשה, `/compact` לפינוי מקום, `/exit` ליציאה.

בפרק הבא נלמד **איך לבקש נכון**: איך לנסח בקשות שמביאות תוצאות טובות כבר בפעם הראשונה.
