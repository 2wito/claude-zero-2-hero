# שילוב כוחות: Cursor + Claude Code

עד עכשיו עבדתם עם Claude Code בחלון טרמינל רגיל. זה עובד, אבל יש בעיה אחת: **אתם לא רואים מה קורה בקבצים**. Claude מספר לכם "יצרתי את הקובץ", "שיניתי שלוש שורות", ואתם צריכים להאמין לו או לפתוח כל קובץ בנפרד.

בפרק הזה נוסיף לתמונה את **Cursor**, עורך קוד שמציג את כל הפרויקט מול העיניים. Claude ממשיך לעבוד בטרמינל, ואתם רואים כל שינוי ברגע שהוא קורה.

<Callout type="note" title="מה תלמדו בפרק">
- למה Cursor ו-Claude Code משלימים זה את זה.
- איך פותחים טרמינל בתוך Cursor ומפעילים בו את Claude.
- איך רואים ובודקים כל שינוי של Claude בחלון השוואה.
- איך עורכים קוד בעצמכם בלי להתנגש עם Claude.
- תרגיל מעשי: מוסיפים פיצ'ר אינטראקטיבי בעבודה משולבת.
</Callout>

## הרעיון: עיניים וידיים

| | **Cursor**: העיניים | **Claude Code**: הידיים |
| --- | --- | --- |
| מה הוא | עורך קוד ויזואלי | סוכן שעובד בטרמינל |
| במה הוא מצוין | לראות את כל הקבצים, לעקוב אחרי שינויים, להשוות גרסאות, תיקונים קטנים ומהירים | משימות שנוגעות בהרבה קבצים, הרצת פקודות, התקנות, תיקון שגיאות |
| מה אתם עושים בו | קוראים, בודקים, מסמנים, משנים מילה פה ושם | מתארים בעברית מה צריך לקרות |

בלי עיניים, הידיים עובדות בחושך: אתם צריכים לסמוך על התיאור של Claude. בלי ידיים, העיניים רק מסתכלות: כל שינוי גדול נשאר עליכם. ביחד מקבלים את הטוב משני העולמות: **Claude עושה את העבודה הכבדה, ואתם רואים ושולטים בכל שלב**.

<Callout type="info" title="ל-Cursor יש בינה מלאכותית משלו. אז למה צריך גם את Claude Code?">
נכון, ב-Cursor יש צ'אט והשלמה אוטומטית של קוד. בפועל, הרבה אנשים משתמשים בשניהם: את ההשלמה האוטומטית של Cursor לתיקונים קטנים תוך כדי הקלדה, ואת Claude Code למשימות גדולות. בקורס הזה Claude Code הוא הכלי המרכזי, ו-Cursor משמש בעיקר כ"חלון" לפרויקט. **אותם עקרונות עובדים גם ב-VS Code**, כי Cursor מבוסס עליו.
</Callout>

## שלב 1: מתקינים את Cursor ופותחים פרויקט

1. הורידו את Cursor מ-[cursor.com](https://cursor.com) והתקינו כמו כל תוכנה. יש גרסאות ל-Windows, ל-Mac ול-Linux.
2. בפתיחה הראשונה Cursor ישאל כמה שאלות הגדרה. אפשר להשאיר את ברירות המחדל.
3. פתחו תיקיית פרויקט: בתפריט העליון בחרו **File → Open Folder...**, ובחרו למשל את התיקייה `my-project` מפרק 3.

<Callout type="tip" title="פותחים תיקייה, לא קובץ">
תמיד פתחו את **כל תיקיית הפרויקט**, ולא קובץ בודד. כך בצד המסך יופיע עץ הקבצים של כל הפרויקט, וכשתפעילו את Claude בטרמינל של Cursor, הוא כבר יהיה בתיקייה הנכונה.
</Callout>

ככה נראה החלון של Cursor. לא צריך לזכור הכול, רק את ארבעת האזורים:

| אזור | איפה | מה יש בו |
| --- | --- | --- |
| **סרגל הפעילות** | הפס הצר בקצה המסך | אייקונים למעבר בין עץ קבצים, חיפוש ו-Source Control |
| **עץ הקבצים** (Explorer) | ליד סרגל הפעילות | כל הקבצים והתיקיות של הפרויקט |
| **אזור העריכה** | באמצע, החלק הגדול | הקבצים הפתוחים, כל אחד בלשונית |
| **הפאנל התחתון** | למטה | הטרמינל, ושם נפעיל את Claude |

## שלב 2: פותחים טרמינל בתוך Cursor ומפעילים את Claude

### פותחים את הטרמינל המובנה

ב-Cursor יש טרמינל מובנה, בדיוק כמו החלון שהשתמשתם בו עד עכשיו, רק בתוך העורך. יש שלוש דרכים לפתוח אותו:

| דרך | איך |
| --- | --- |
| **קיצור מקלדת** | `` Ctrl + ` `` (המקש משמאל ל-1, שעליו מופיע גם `~`) |
| **תפריט** | **View → Terminal**, או **Terminal → New Terminal** |
| **הצגה והסתרה של הפאנל** | `Ctrl + J` ב-Windows וב-Linux, `Cmd + J` ב-Mac |

<Callout type="note" title="הקיצור לא עובד?">
אם המקלדת על עברית, המקש `` ` `` כותב משהו אחר, ולפעמים הקיצור לא מגיב. עברו לאנגלית (`Alt + Shift` ב-Windows, `Ctrl + רווח` ב-Mac) ונסו שוב, או פשוט השתמשו בתפריט **View → Terminal**, שעובד תמיד.
</Callout>

### מפעילים את Claude

הטרמינל נפתח כבר בתוך תיקיית הפרויקט, אז אין צורך ב-`cd`. פשוט מקלידים:

```bash title="בטרמינל של Cursor"
claude
```

<Callout type="info" title="Claude Code מתחבר ל-Cursor לבד">
כשמפעילים את `claude` בטרמינל **של** Cursor, הוא מזהה את העורך ומתחבר אליו אוטומטית. בפעם הראשונה הוא עשוי להתקין בעורך תוסף קטן של Claude Code, כדי שהחיבור יעבוד. מה החיבור הזה נותן:

- **השינויים שClaude מציע נפתחים בחלון ההשוואה של Cursor**, ולא רק כטקסט בטרמינל.
- **Claude רואה מה סימנתם בעורך**: מסמנים כמה שורות, ו-Claude יודע עליהן בלי שתעתיקו אותן.
- **Claude רואה את השגיאות** שמופיעות בחלון Problems של Cursor.
</Callout>

אם הפעלתם את `claude` בטרמינל רגיל מחוץ ל-Cursor, או שלא בטוחים שהחיבור עובד, הריצו בתוך Claude Code את הפקודה הזאת. היא מראה לאיזה עורך Claude מחובר, ומאפשרת להתחבר:

```text title="בתוך Claude Code"
/ide
```

### מסדרים את המסך: עורך מצד אחד, Claude מהצד השני

כברירת מחדל הטרמינל נפתח למטה, וזה צפוף. הסידור הכי נוח הוא **זה לצד זה**: קוד מצד אחד, Claude מהצד השני.

1. פתחו את לוח הפקודות של Cursor: `Ctrl + Shift + P` (ב-Mac: `Cmd + Shift + P`).
2. הקלידו `Terminal in Editor Area` ובחרו באפשרות שיוצרת טרמינל **באזור העריכה, בצד** (to the Side).
3. בטרמינל החדש הפעילו `claude`.

עכשיו הטרמינל מתנהג כמו עוד לשונית באזור העריכה, ואפשר לגרור אותו לאיזה צד שנוח לכם.

<Callout type="tip" title="ואם יש גם שרת פיתוח?">
בפרויקטים כמו של פרק 6 צריך גם חלון שבו רץ `npm run dev`. השאירו את הטרמינל התחתון בשבילו, ואת הטרמינל שבצד בשביל Claude. כך הכול בחלון אחד: קוד, Claude ושרת.
</Callout>

<Callout type="note" title="יש גם דרך גרפית">
במקום להפעיל את Claude בטרמינל, אפשר להשתמש ב**תוסף של Claude Code** ש-Cursor תומך בו. התוסף פותח את Claude בפאנל צד עם ממשק גרפי. כדי להתקין: פותחים את מסך התוספים (`Ctrl + Shift + X`, ב-Mac: `Cmd + Shift + X`) ומחפשים **Claude Code** של Anthropic. בקורס נמשיך עם הטרמינל, כי שם זמינות כל הפקודות, אבל התוסף נוח מאוד למי שמעדיף ממשק גרפי.
</Callout>

## שלב 3: צופים בשינויים בזמן אמת

זה הרגע שבו העבודה המשולבת מתחילה להשתלם.

### רואים את הקבצים משתנים

כש-Claude יוצר או משנה קובץ, הוא מופיע מיד בעץ הקבצים, והתוכן שלו מתעדכן בעורך. אם הקובץ פתוח אצלכם בלשונית, תראו את השינוי קורה מול העיניים.

ליד מספרי השורות יופיעו פסים צבעוניים שמסמנים מה השתנה מאז השמירה האחרונה ב-Git:

| סימן | משמעות |
| --- | --- |
| פס **ירוק** | שורות חדשות שנוספו |
| פס **כחול** | שורות קיימות ששונו |
| משולש **אדום** | כאן נמחקו שורות |

לחיצה על הפס מציגה בדיוק מה היה שם קודם.

### בודקים שינוי לפני שמאשרים

אם אתם במצב **manual**, כל עריכה של Claude מחכה לאישור שלכם. בזכות החיבור ל-Cursor, השינוי המוצע נפתח ב**חלון השוואה** (Diff): הגרסה הנוכחית בצד אחד והגרסה המוצעת בצד השני, עם הדגשה של כל מה שמשתנה. ככה נראה שינוי כזה כשמציגים אותו כטקסט:

```diff title="index.html: שינוי מוצע"
   <h1>יום הולדת שמח, סבתא!</h1>
-  <p>מאחלים לך בריאות ואושר</p>
+  <p>מאחלים לך בריאות, אושר והמון נחת מהנכדים</p>
+  <button id="confetti-btn">🎉 לחגוג!</button>
```

שורות עם `-` נמחקות, ושורות עם `+` נוספות. קראו, ואז אשרו או סרבו בטרמינל, בדיוק כמו בפרק 3.

### סקירה של כל השינויים אחרי משימה (Source Control)

אחרי שClaude סיים משימה גדולה, כדאי לעבור על **כל** מה שהשתנה, במקום אחד:

1. לחצו על אייקון **Source Control** בסרגל הפעילות (נראה כמו ענף עם עיגולים), או `Ctrl + Shift + G` (ב-Mac: `Cmd + Shift + G`).
2. תופיע רשימה של כל הקבצים שהשתנו. האות שליד כל קובץ מסמנת מה קרה לו: **M** שונה, **U** חדש, **D** נמחק.
3. לחצו על קובץ, ותיפתח השוואה צד-לצד: מצד אחד הגרסה השמורה האחרונה, מהצד השני הגרסה הנוכחית.

<Callout type="warning" title="Source Control עובד רק בפרויקט עם Git">
הרשימה הזאת מבוססת על Git, ולכן היא מופיעה רק אם בתיקייה הוגדר Git. פרויקטים של Next.js (כמו בפרק 6) כבר מגיעים עם Git. בפרויקט אחר, בקשו מ-Claude: "תאתחל git בתיקייה ותשמור את המצב הנוכחי כנקודת התחלה". ב-Windows צריך להתקין קודם את [Git for Windows](https://git-scm.com/downloads/win). בפרק 8 נלמד את Git לעומק.
</Callout>

<Callout type="tip" title="בודקים כמו מנהלים">
לא צריך להבין כל שורת קוד כדי לבדוק. שאלו את עצמכם: **האם השתנו רק הקבצים שציפיתי?** אם ביקשתם לשנות כפתור ופתאום השתנו שבעה קבצים, זה הזמן לשאול את Claude למה. ואם משהו לא ברור, סמנו אותו בעורך ושאלו: "מה השורות שסימנתי עושות?"
</Callout>

### מצביעים במקום לתאר: סימון בעורך

זה אחד היתרונות הכי חזקים של העבודה המשולבת. במקום להסביר ל-Claude **איפה** משהו נמצא, פשוט **סמנו** אותו בעורך עם העכבר, ואז כתבו לו בטרמינל. Claude מקבל את השורות שסימנתם יחד עם ההודעה, ובטרמינל תופיע שורה כמו `⧉ Selected 6 lines from index.html`.

## שלב 4: עורכים בעצמכם בלי להתנגש עם Claude

אחד היתרונות של Cursor הוא שאפשר לשנות דברים קטנים **בעצמכם**: לתקן מילה, לשנות צבע או מספר. זה מהיר יותר מלבקש מ-Claude. אבל כששניים עובדים על אותם קבצים, צריך כמה כללי תנועה.

### איך נוצרת התנגשות?

דמיינו שניים שכותבים על אותו דף בו זמנית. ב-Cursor זה קורה בשני מצבים:

1. **שינוי שלא נשמר.** שיניתם משהו בעורך ולא שמרתם (`Ctrl + S`). השינוי קיים **רק בעורך**, לא בקובץ עצמו, ולכן Claude לא רואה אותו. אם Claude ישנה את אותו קובץ, יהיו שתי גרסאות שונות.
2. **עריכה באותו רגע.** אתם מקלידים בקובץ בדיוק כשClaude עורך אותו.

כשזה קורה, Cursor יציג בזמן השמירה הודעה בנוסח **"The content of the file is newer"** (תוכן הקובץ חדש יותר). בחרו **Compare** כדי לראות את שתי הגרסאות זו מול זו, ולא **Overwrite**, שדורס את השינויים של Claude.

<Callout type="info" title="Claude Code שומר על עצמו">
לפני שClaude עורך קובץ הוא קורא אותו, ואם הקובץ השתנה מאז הקריאה האחרונה, הוא קורא אותו שוב לפני העריכה. לכן שינויים **ששמרתם** בדרך כלל לא הולכים לאיבוד. הבעיה העיקרית היא שינויים **שלא נשמרו**.
</Callout>

### שבעה כללי תנועה

1. **שומרים לפני ששולחים.** לפני כל בקשה ל-Claude, `Ctrl + S` (ב-Mac: `Cmd + S`). או, עוד יותר טוב, הפעילו שמירה אוטומטית (ראו בהמשך).
2. **לא נוגעים בקובץ שClaude עורך עכשיו.** Claude עובד על `index.html`? חכו שיסיים, או לחצו `Esc` כדי לעצור אותו לפני שאתם נכנסים.
3. **מחלקים טריטוריה.** בזמן שClaude עובד על הלוגיקה ב-`script.js`, אתם יכולים לשנות טקסטים ב-`index.html`. קבצים שונים = אפס התנגשויות.
4. **מספרים ל-Claude מה שיניתם.** שיניתם משהו בעצמכם? ציינו את זה בבקשה הבאה, כדי שלא "יתקן" לכם את השינוי בחזרה.
5. **שומרים נקודת ביטחון לפני משימה גדולה.** "תשמור את המצב הנוכחי ב-git" לוקח שניות, ומאפשר לחזור אחורה אם משהו משתבש.
6. **סוכן אחד בכל פעם.** אל תפעילו את הסוכן המובנה של Cursor ואת Claude Code על אותם קבצים באותו זמן. בחרו אחד לכל משימה.
7. **בספק? בודקים את Source Control.** הוא מראה בדיוק מה השתנה ואיפה, לא משנה מי שינה.

<PromptCompare
  bad="תמשיך מאיפה שהפסקנו"
  good="שיניתי בעצמי את התאריך ואת שם הכותרת ב-index.html. תקרא את הקובץ מחדש, תשאיר את השינויים שלי כמו שהם, ותמשיך להוסיף את טיימר הספירה לאחור."
  why="בלי המשפט הזה, Claude עלול להחזיר את מה שהוא עצמו כתב קודם. עם המשפט הזה, השינויים שלכם בטוחים."
/>

### הפעלת שמירה אוטומטית

הדרך הכי פשוטה להיפטר מבעיית השינויים שלא נשמרו: בתפריט העליון, **File → Auto Save**. כשיש V ליד האפשרות, כל שינוי נשמר לבד אחרי שנייה.

למי שמעדיף להגדיר דרך קובץ ההגדרות (לוח הפקודות → `Preferences: Open User Settings (JSON)`):

```json title="settings.json (הגדרות Cursor)"
{
  "files.autoSave": "afterDelay",
  "files.autoSaveDelay": 1000
}
```

## תרגיל מעשי: ספירה לאחור וקיר ברכות

נחזור לדף יום ההולדת של סבתא מפרק 3, ונוסיף לו שני פיצ'רים אינטראקטיביים: **ספירה לאחור** עד יום ההולדת, ו**קיר ברכות** שבו כל אחד יכול להשאיר איחול. העבודה תתחלק: Claude בונה, ואתם רואים, מכוונים ומשנים פרטים בעצמכם.

<Callout type="note" title="אין לכם את הדף מפרק 3?">
אין בעיה. פתחו ב-Cursor תיקייה ריקה, הפעילו `claude` ובקשו: "צור דף index.html עם ברכת יום הולדת לסבתא, בעברית ומימין לשמאל, עם עיצוב צבעוני ושמח".
</Callout>

### חלק א': הכנה

1. פתחו את התיקייה `my-project` ב-Cursor (**File → Open Folder...**).
2. הפעילו שמירה אוטומטית (**File → Auto Save**).
3. פתחו טרמינל בצד (לוח הפקודות → `Terminal in Editor Area`) והפעילו `claude`.
4. עברו למצב **manual** עם `Shift + Tab`, כדי לראות כל שינוי לפני שהוא קורה.
5. פתחו את `index.html` בעורך, ופתחו את הקובץ גם בדפדפן (לחיצה כפולה עליו בתיקייה).
6. אם מותקן אצלכם Git, בקשו מ-Claude לשמור נקודת התחלה:

<Prompt>תאתחל git בתיקייה הזאת ותשמור את המצב הנוכחי כנקודת התחלה, עם הודעה ״לפני ספירה לאחור וקיר ברכות״</Prompt>

### חלק ב': Claude בונה את הספירה לאחור

<Prompt>תוסיף לדף ספירה לאחור עד יום ההולדת של סבתא: ימים, שעות, דקות ושניות, שמתעדכנים כל שנייה. תשים את הקוד בקובץ נפרד בשם script.js, ובתחילת הקובץ משתנה אחד עם תאריך יום ההולדת, כדי שיהיה קל לשנות אותו. כשמגיע היום, במקום הספירה תופיע הכותרת ״היום זה היום! 🎂״.</Prompt>

**מה לעשות בזמן שClaude עובד:**

- צפו בעץ הקבצים: `script.js` חדש יופיע.
- כשתופיע בקשת אישור לשינוי ב-`index.html`, קראו את ההשוואה. אמורה להיות תוספת של אזור לספירה ושל קישור ל-`script.js`.
- אשרו, ורעננו את הדפדפן. הספירה רצה?

### חלק ג': הידיים שלכם

עכשיו תורכם. פתחו את `script.js` בעורך. בתחילת הקובץ תמצאו שורה שנראית בערך כך:

```js title="script.js"
const BIRTHDAY = new Date("2026-12-25T00:00:00");
```

**שנו בעצמכם את התאריך** לתאריך יום הולדת אמיתי במשפחה (שנה-חודש-יום), שמרו, ורעננו את הדפדפן. הספירה השתנתה? מעולה: עשיתם שינוי קוד ראשון בעצמכם, בלי לבקש מאף אחד.

<Callout type="tip" title="למה לא לבקש מ-Claude?">
אפשר, כמובן. אבל שינוי של מספר אחד בשורה שאתם רואים מול העיניים מהיר יותר מניסוח בקשה. זה בדיוק הכוח של העבודה המשולבת: **שינויים קטנים וידועים בידיים שלכם, שינויים גדולים או לא ידועים אצל Claude**.
</Callout>

### חלק ד': Claude בונה קיר ברכות, ואתם מכוונים עם סימון

<Prompt>שיניתי בעצמי את התאריך ב-script.js, תשאיר אותו כמו שהוא. עכשיו תוסיף מתחת לספירה ״קיר ברכות״: טופס עם שדה לשם ושדה לברכה וכפתור ״הוספת ברכה״. כל ברכה מופיעה ככרטיס צבעוני עם השם, והברכות נשמרות בדפדפן כך שהן נשארות גם אחרי רענון. אם אחד השדות ריק, תופיע הודעה ידידותית ולא תתווסף ברכה.</Prompt>

אחרי שהקיר עובד, נשתמש בסימון:

1. ב-`index.html`, **סמנו עם העכבר** את הקוד של אזור קיר הברכות.
2. כתבו ל-Claude בטרמינל:

<Prompt>תעצב את האזור שסימנתי: כל כרטיס ברכה בצבע פסטל אחר, פינות מעוגלות, והברכה החדשה ביותר מופיעה ראשונה. בטלפון כרטיס אחד בשורה, במחשב שלושה.</Prompt>

3. שימו לב לשורה `⧉ Selected ... lines from index.html` בטרמינל. כך אתם יודעים שClaude קיבל את הסימון.

## סיכום

- **Cursor הוא העיניים, Claude Code הוא הידיים.** Claude עושה את העבודה, ואתם רואים כל שינוי.
- **טרמינל ב-Cursor**: `` Ctrl + ` `` או **View → Terminal**, ואז `claude`. החיבור לעורך קורה אוטומטית, ומטרמינל חיצוני מתחברים עם `/ide`.
- **סקירת שינויים**: פסים צבעוניים ליד השורות, חלון השוואה לפני אישור, ו-Source Control אחרי משימה.
- **סימון בעורך** אומר ל-Claude בדיוק על מה מדובר, וחלון Problems מראה לו את השגיאות.
- **בלי התנגשויות**: שומרים (או מפעילים Auto Save), לא עורכים קובץ שClaude עובד עליו, ומספרים לו על שינויים ידניים.
