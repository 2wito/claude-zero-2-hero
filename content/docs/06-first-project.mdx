# פרויקט מעשי ראשון: בונים אתר מאפס

עד עכשיו למדתם את הכלים. בפרק הזה משתמשים בכולם יחד: נבנה **אתר מתכונים משפחתי שלם**, מתיקייה ריקה ועד אתר שעובר בדיקות איכות ומוכן לעלות לאוויר.

באתר יהיו:

- **דף בית** עם כרטיס לכל מתכון.
- **דף נפרד לכל מתכון**, עם מצרכים ושלבי הכנה.
- **חיפוש וסינון לפי קטגוריה** (עוגות, מרקים, תבשילים).
- **מחשבון מנות**: רוצים לבשל לעשרה אנשים במקום לארבעה? הכמויות מתעדכנות לבד.
- **סימון שלבים**: מסמנים כל שלב שסיימתם תוך כדי בישול.
- **בונוס**: טופס להוספת מתכון חדש, שנשמר בצד השרת.

<Callout type="note" title="מה צריך לפני שמתחילים">
- Claude Code מותקן ומחובר (פרק 2).
- היכרות עם פקודות בסיסיות ובקשות אישור (פרק 3) ועם העקרונות לניסוח בקשות (פרק 4).
- **Cursor** מותקן, והיכרות עם העבודה המשולבת מפרק 5. את כל הפרויקט נבנה בתוכו.
- **Node.js** מותקן במחשב. אם עוד לא, ההוראות מיד למטה.
- בערך **שעתיים**. לא חייבים בבת אחת: כל שלב נגמר באתר שעובד, ואפשר לעצור ולהמשיך מחר.
</Callout>

## הכלים שנשתמש בהם

לא צריך להכיר אותם לעומק. Claude מכיר אותם מצוין, ואתם צריכים רק לדעת מה כל אחד עושה:

| כלי | מה הוא עושה | משל |
| --- | --- | --- |
| **Node.js** | מריץ קוד JavaScript על המחשב שלכם | המנוע |
| **npm** | מתקין חבילות קוד ומריץ פקודות של הפרויקט (מגיע יחד עם Node.js) | חנות החלקים |
| **Next.js** | מסגרת לבניית אתרים: דפים, ניווט, שרת | שלד הבית |
| **Tailwind CSS** | דרך מהירה לעצב, ישירות בתוך הקוד | צבע וריהוט |

<Callout type="info" title="למה Next.js?">
Next.js מטפל גם במה שהגולשים רואים (Frontend) וגם במה שקורה מאחורי הקלעים (Backend), כך שאפשר לבנות אתר שלם בפרויקט אחד. זו גם בדיוק הטכנולוגיה שבה בנוי האתר שאתם קוראים עכשיו, והיא עולה לאוויר בקלות ב-Vercel, שבה נשתמש בפרק 9.
</Callout>

## שלב 0: מתקינים Node.js

בדקו קודם אם הוא כבר מותקן:

```bash title="בכל מערכת הפעלה"
node -v
npm -v
```

אם מופיעים שני מספרי גרסה, למשל `v22.11.0` ו-`10.9.0`, אפשר לדלג לשלב 1. אם מופיעה שגיאה כמו "not recognized" או "command not found", התקינו:

<Tabs groupId="os" items={["Windows PowerShell", "Windows CMD", "macOS / Linux"]}>
<Tab>

```powershell title="Windows PowerShell"
winget install OpenJS.NodeJS.LTS
```

או הורידו את גרסת **LTS** מ-[nodejs.org](https://nodejs.org) והריצו את קובץ ההתקנה.

</Tab>
<Tab>

```bat title="Windows CMD"
winget install OpenJS.NodeJS.LTS
```

או הורידו את גרסת **LTS** מ-[nodejs.org](https://nodejs.org) והריצו את קובץ ההתקנה.

</Tab>
<Tab>

ב-Mac, הדרך הכי פשוטה היא להוריד את גרסת **LTS** מ-[nodejs.org](https://nodejs.org). אם יש לכם Homebrew:

```bash title="macOS (Homebrew)"
brew install node
```

ב-Linux, ההוראות לכל הפצה נמצאות באתר [nodejs.org](https://nodejs.org/en/download).

</Tab>
</Tabs>

אחרי ההתקנה **סגרו ופתחו את הטרמינל מחדש**, והריצו שוב `node -v` כדי לוודא.

<Callout type="tip" title="LTS = הגרסה היציבה">
LTS (קיצור של Long Term Support) היא הגרסה שמקבלת תמיכה ועדכוני אבטחה לאורך זמן. תמיד בחרו בה, ולא בגרסה "Current".
</Callout>

את כל הפרויקט נבנה בתוך Cursor, בדיוק כמו בפרק 5: Claude עובד בטרמינל, ואתם רואים כל קובץ נוצר ומשתנה.

**פותחים אותה ב-Cursor ומסדרים את סביבת העבודה:**

1. ב-Cursor: **File → Open Folder...** ובחרו את `grandma-recipes`.
2. הפעילו שמירה אוטומטית: **File → Auto Save**. בפרויקט שבו גם אתם וגם Claude עורכים קבצים, זה חוסך התנגשויות (פרק 5).
3. פתחו טרמינל בצד: לוח הפקודות (`Ctrl + Shift + P`, ב-Mac: `Cmd + Shift + P`) ← `Terminal in Editor Area`.


</Callout>

**הסתכלו על עץ הקבצים של Cursor** בזמן ההתקנה: התיקייה הריקה מתמלאת בקבצים ובתיקיות כמו `app`, `public` ו-`package.json`. כשClaude מסביר מה כל תיקייה עושה, לחצו עליה בעץ ותראו בעצמכם מה יש בה.

### 1.3 מריצים בפעם הראשונה

כדי לראות את האתר, צריך להפעיל **שרת פיתוח**: תוכנה שמריצה את האתר על המחשב שלכם ומרעננת אותו אוטומטית בכל שינוי.

שרת הפיתוח רץ ברציפות עד שעוצרים אותו, ולכן הוא צריך **טרמינל משלו**, נפרד מזה של Claude. ב-Cursor, פתחו את הטרמינל התחתון עם `` Ctrl + ` `` (או **View → Terminal**). הוא כבר נמצא בתיקיית הפרויקט, אז אין צורך ב-`cd`. הריצו:

```bash title="בטרמינל התחתון של Cursor"
npm run dev
```

```text title="פלט לדוגמה"
   ▲ Next.js 15.5.4 (Turbopack)
   - Local:        http://localhost:3000
   - Network:      http://192.168.1.12:3000

 ✓ Starting...
 ✓ Ready in 1820ms
```

פתחו בדפדפן את הכתובת **http://localhost:3000**. אפשר גם להחזיק `Ctrl` (ב-Mac: `Cmd`) וללחוץ על הכתובת בטרמינל. תראו את דף ברירת המחדל של Next.js. זה עדיין לא האתר שלנו, אבל זה סימן שהכול עובד.

<Callout type="info" title="מה זה localhost:3000?">
`localhost` אומר "המחשב הזה". האתר רץ רק אצלכם, ואף אחד אחר באינטרנט לא רואה אותו. `3000` הוא מספר ה"דלת" (Port) שהשרת מקשיב לה. כדי לעצור את השרת, לוחצים `Ctrl + C` בחלון שבו הוא רץ.
</Callout>

מעכשיו, ככה נראית סביבת העבודה לאורך כל הפרויקט:

| איפה | מה רץ שם | התפקיד |

<Callout type="tip" title="שני מסכים? מצוין">
אם יש לכם מסך נוסף, שימו עליו את הדפדפן. כך תראו את הקוד, את Claude ואת האתר באותו זמן, בלי לעבור בין חלונות.

## שלב 2: בונים מבנה, עיצוב ורכיבים, צעד אחר צעד

זוכרים את כלל הפירוק מפרק 4? לא מבקשים את כל האתר בבת אחת. בונים שכבה אחרי שכבה, ובודקים כל אחת בדפדפן.

### 2.1 מתכננים לפני שבונים

נעבור למצב תכנון, כדי ש-Claude יציע מבנה לפני שהוא כותב קוד:

<Prompt>/plan אנחנו בונים אתר מתכונים משפחתי. בשלב הזה רק: קובץ נתונים עם 6 מתכונים לדוגמה, דף בית שמציג כרטיס לכל מתכון, ודף נפרד לכל מתכון עם מצרכים ושלבי הכנה. תציע מבנה תיקיות ורשימת רכיבים (Components), ותסביר במשפט אחד מה כל רכיב עושה. עוד לא כותבים קוד.</Prompt>

Claude יציג תוכנית שנראית בערך כך:

```text title="תוכנית לדוגמה"
lib/recipes.ts                  נתוני המתכונים (6 מתכונים לדוגמה)
app/layout.tsx                  מסגרת האתר: עברית, RTL, גופן, כותרת ותחתית
app/page.tsx                    דף הבית: רשת של כרטיסי מתכונים
app/recipes/[slug]/page.tsx     דף מתכון בודד
components/RecipeCard.tsx       כרטיס מתכון: אימוג'י, שם, זמן הכנה, קטגוריה
components/SiteHeader.tsx       כותרת האתר וניווט
```

קראו את התוכנית. משהו חסר או מיותר? אמרו לו. כשהיא נראית טובה, אשרו, ו-Claude יעבור לביצוע. תוך כדי, הסתכלו על עץ הקבצים: הקבצים מהתוכנית יופיעו בו אחד אחרי השני.

<Callout type="note" title="מה זה [slug]?">
תיקייה בשם `[slug]` עם סוגריים מרובעים היא דרך של Next.js להגיד "דף אחד שמשמש את כל המתכונים". `slug` הוא השם של המתכון בכתובת, למשל `/recipes/grandma-cheesecake`.
</Callout>

### 2.2 קובץ הנתונים

אם Claude לא התחיל מהנתונים בעצמו, בקשו:

<Prompt>תתחיל מקובץ הנתונים lib/recipes.ts. לכל מתכון: שם, slug באנגלית, קטגוריה (עוגות, מרקים או תבשילים), זמן הכנה בדקות, מספר מנות, אימוג'י שמייצג אותו, רשימת מצרכים שבה לכל מצרך יש כמות, יחידה ושם, ורשימת שלבי הכנה. 6 מתכונים ביתיים ישראליים לדוגמה, שניים מכל קטגוריה.</Prompt>

<Callout type="tip" title="למה כמות ויחידה בנפרד?">
שימו לב לבקשה: "כמות, יחידה ושם" בנפרד, ולא "2 כוסות קמח" כטקסט אחד. זה תכנון קדימה: בשלב 3 נבנה מחשבון מנות, והוא צריך לדעת שהמספר הוא 2 כדי להכפיל אותו. החלטות קטנות בהתחלה חוסכות עבודה גדולה בהמשך.
</Callout>

### 2.3 המסגרת: עברית, RTL וגופן

<Prompt>שיניתי בעצמי את שם אחד המתכונים ב-lib/recipes.ts, תשאיר אותו כמו שהוא. עכשיו תעדכן את app/layout.tsx: שפה עברית וכיוון מימין לשמאל, גופן עברי קריא מ-Google Fonts דרך next/font (Rubik או Heebo), כותרת עליונה עם שם האתר ״המתכונים של סבתא״ שמובילה לדף הבית, ותחתית פשוטה. תמחק את התוכן של דף ברירת המחדל של Next.js. תצבע ברקע חם ונעים, בלי לבן בוהק.</Prompt>

## מה עשינו כאן, בעצם?

תסתכלו רגע אחורה. בניתם אתר אינטרנט שלם, עם חיפוש, מחשבון מנות, שמירת נתונים ובדיקות איכות. את רוב הקוד כתב Claude, ואתם שיניתם בעצמכם רק כמה שורות. אבל **עשיתם** את כל מה שחשוב:

- **תכננתם**: החלטתם מה האתר עושה ופירקתם אותו לשלבים.
- **ניסחתם**: כתבתם בקשות ספציפיות עם הקשר ודרך לבדוק.
- **בדקתם**: עברתם על השינויים ב-Cursor ובדפדפן אחרי כל שכבה, ותפסתם בעיות מוקדם.
- **ערכתם בעצמכם**: שינויים קטנים עשיתם ביד, ולשינויים גדולים הצבעתם ל-Claude עם סימון.
- **הקשבתם**: הפכתם משוב של משתמשים אמיתיים לשיפורים.
- **וידאתם**: בנייה לייצור, בדיקת איכות ובדיקה ידנית לפני שמעלים.

זו בדיוק העבודה של מנהל מוצר ושל מפתח מנוסה. Claude כתב את הקוד, ואתם הובלתם.

<Callout type="note" title="הפרויקט שלכם, הכללים שלכם">
אתר המתכונים הוא רק דוגמה. אותו תהליך בדיוק עובד לדף נחיתה לעסק, לאתר תיק עבודות, לאלבום תמונות משפחתי או לכל רעיון אחר. הכול מתחיל באותם ארבעה שלבים: מקימים, בונים בשכבות, משפרים לפי משוב, ובודקים לפני שמעלים.
</Callout>
