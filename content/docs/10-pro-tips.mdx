# טיפים של אלופים וקיצורי דרך

הגעתם לפרק שסוגר את המסלול הבסיסי. אתם כבר יודעים להתקין, לבקש, לבנות, לתקן, לשמור ב-Git ולהעלות לאוויר. הפרק הזה הוא על **השכבה הבאה**: ההרגלים הקטנים שמפרידים בין מי שמשתמש ב-Claude Code לבין מי שעובד איתו כמו מקצוען.

<Callout type="note" title="מה תלמדו בפרק">
- לחסוך בטוקנים ובעלויות, ולהישאר בתוך מגבלות המנוי.
- להפוך את CLAUDE.md לכלי מתקדם: כללים לפי קבצים, ייבוא קבצים והוראות לסיכום.
- לחבר את Claude לכלים חיצוניים עם **MCP**.
- קיצורי דרך שחוסכים זמן כל יום.
- ובסוף: סיכום של כל הקורס, רשימת בדיקה, ולאן ממשיכים מכאן.
</Callout>

## חלק 1: חיסכון בטוקנים ובעלויות

### איך זה עובד: למה שיחה ארוכה "יקרה"

**טוקן** (Token) הוא יחידת המדידה של מודלי שפה: בערך חלק של מילה. כל דבר ש-Claude קורא או כותב נמדד בטוקנים, וזה מה שקובע את העלות (בחשבון Console) או כמה מהר תגיעו למגבלת השימוש (במנוי).

הנקודה החשובה: **בכל הודעה, Claude Code שולח למודל את כל השיחה מההתחלה**, כולל כל קובץ שנקרא וכל פלט של פקודה. שאלה קצרה בשיחה שפתוחה כבר שלוש שעות "עולה" הרבה יותר מאותה שאלה בשיחה חדשה. Claude Code משתמש במנגנון שמירה זמנית (Prompt Caching) שמוזיל את החזרה על אותו תוכן, אבל עדיין: **שיחה קצרה וממוקדת היא שיחה זולה**.

### לראות לאן הולכים הטוקנים

| פקודה | מה היא מראה |
| --- | --- |
| `/usage` | השימוש שלכם: במנוי, כמה ממגבלת השימוש כבר נוצלה. ב-Console, הערכת עלות של הסשן. יש בה גם המלצות לחיסכון |
| `/context` | מה ממלא את חלון ההקשר כרגע: השיחה, CLAUDE.md, כלים, קבצים |
| `/insights` | דוח על **איך** אתם עובדים: איפה יש חיכוכים, ומה אפשר לשפר |

<Callout type="tip" title="המלצות בלחיצה אחת">
במנוי Pro או Max, `/usage` מציג גם פירוט של מה צורך את המגבלה, עם המלצות כמו "תקצרו את CLAUDE.md". כשמופיע בתחתית הרמז `f to fix`, לחיצה על `f` מבקשת מ-Claude ליישם את ההמלצות שהוא יכול, והוא מראה לכם כל שינוי לפני שהוא עושה אותו.
</Callout>

### עשרה הרגלים שחוסכים

1. **`/clear` בין משימות שלא קשורות.** זה חינם, וזה החיסכון הכי גדול. סיימתם עם העיצוב ועוברים לבאג? שיחה חדשה.
2. **`/rename` לפני `/clear`.** תנו לשיחה שם, למשל `/rename עיצוב-דף-הבית`, ותוכלו למצוא אותה אחר כך עם `/resume`.
3. **`/compact` עם הנחיה, באמצע משימה ארוכה.** במקום לחכות לסיכום האוטומטי, סכמו בנקודת עצירה טבעית, והגידו מה לשמור:

```text title="בתוך Claude Code"
/compact תשמור את התוכנית, את רשימת הקבצים ששינינו, ואת הבאג שעוד לא פתרנו
```

4. **בקשות ספציפיות.** "תשפר את הפרויקט" גורם ל-Claude לסרוק הכול. "תוסיף בדיקה לשדה האימייל ב-ContactForm.tsx" קורא קובץ אחד.
5. **`@קובץ` במקום "תמצא איפה".** הפניה ישירה חוסכת חיפוש בכל הפרויקט.
6. **מצב תכנון למשימות גדולות.** תוכנית שגויה שמתגלה בשלב התכנון עולה כמה הודעות. תוכנית שגויה שמתגלה אחרי ביצוע עולה הכול פעמיים.
7. **`Esc` מוקדם.** רואים כיוון לא נכון? עצרו מיד, במקום לחכות שיסיים ואז לתקן.
8. **המודל המתאים למשימה.** עם `/model` אפשר לבחור מודל. מודל חזק יותר טוב להחלטות מורכבות, ומודל קל יותר מספיק למשימות פשוטות ועולה פחות. עם `/effort` אפשר גם להוריד את רמת המאמץ (כמה "לחשוב") במשימות פשוטות.
9. **סוכני משנה לעבודה "רועשת".** הרצת בדיקות, קריאת לוגים ארוכים או חיפוש בהרבה קבצים: "תשתמש בסוכן משנה כדי..." משאיר את הפלט הארוך מחוץ לשיחה הראשית.
10. **`/btw` לשאלות צד.** שאלה קטנה שלא קשורה למשימה, למשל "רגע, מה זה useEffect?", לא צריכה להישאר בשיחה. התשובה ל-`/btw` לא נכנסת להיסטוריה.

### ומה עם `.claudeignore`?

ברשת אפשר למצוא המלצה ליצור קובץ `.claudeignore` כדי ש-Claude "לא יראה" קבצים מסוימים, כמו `.gitignore`.

<Callout type="warning" title=".claudeignore לא עובד">
לפי התיעוד הרשמי של Claude Code, לקובץ `.claudeignore` **אין שום השפעה**. אם יש לכם כזה, הוא לא מגן על כלום. כדי למנוע מ-Claude לקרוא קבצים, משתמשים ב**חוקי `deny` לקריאה** בקובץ ההגדרות, כמו בחוקי Git שלמדנו בפרק 8.
</Callout>

הנה הדרך הנכונה. הקובץ הזה חוסם את Claude מלקרוא קבצי סודות ותיקיות גדולות שאין סיבה לקרוא:

```json title=".claude/settings.json"
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(./data/backups/**)"
    ]
  }
}
```

<Callout type="note" title="שתי מטרות, שני כלים">
- **אבטחה** (שClaude לא יקרא סודות): חוקי `Read` ב-`deny`, כמו בדוגמה.
- **חיסכון** (שClaude לא יבזבז זמן על קבצים לא רלוונטיים): תיקיות כמו `node_modules`, `.next` ו-`dist` צריכות להיות ב-`.gitignore` ממילא. Claude Code מתחשב בו בחיפושים, וכך גם לא ייבנו פלטים מיותרים.
</Callout>

## חלק 2: CLAUDE.md ברמת אלופים

בפרק 4 למדנו את היסודות: CLAUDE.md נטען בכל שיחה, צריך להיות קצר וספציפי, ונוצר עם `/init`. עכשיו נשדרג.

### היררכיה: איזה CLAUDE.md נטען מתי

| קובץ | חל על | נטען |
| --- | --- | --- |
| `~/.claude/CLAUDE.md` | אתם, בכל הפרויקטים | בכל שיחה |
| `CLAUDE.md` בשורש הפרויקט | הפרויקט, וכל מי שעובד עליו | בכל שיחה בפרויקט |
| `CLAUDE.local.md` בשורש הפרויקט | רק אתם, רק בפרויקט הזה (מוסיפים ל-`.gitignore`) | בכל שיחה בפרויקט |
| `CLAUDE.md` בתת-תיקייה, למשל `app/admin/` | רק החלק הזה של הפרויקט | כש-Claude עובד על קבצים בתיקייה |
| `.claude/rules/*.md` | נושא אחד, או סוג קבצים מסוים | תמיד, או רק כשנוגעים בקבצים מתאימים |

### כלל 1: העדפות אישיות פעם אחת, לכל הפרויקטים

דברים שנכונים לכל הפרויקטים שלכם, שימו ב-`~/.claude/CLAUDE.md` ותשכחו מהם:

```markdown title="~/.claude/CLAUDE.md"
# העדפות אישיות
- תענה לי בעברית, בשפה פשוטה. מונחים טכניים באנגלית, עם הסבר קצר בפעם הראשונה.
- לפני שינוי שנוגע ביותר משלושה קבצים, תציג תוכנית ותחכה לאישור.
- הודעות git באנגלית: שורה ראשונה קצרה שמתארת מה ולמה.
- אף פעם לא git push --force, ואף פעם לא push ישירות ל-main.
```

### כלל 2: כללים לפי סוג קובץ (`.claude/rules/`)

בפרויקט גדול, חלק מהכללים רלוונטיים רק לחלק מהקבצים. במקום לנפח את CLAUDE.md, שמים אותם בקבצים נפרדים בתיקייה `.claude/rules/`. עם השדה `paths`, הכלל נטען **רק** כש-Claude עובד על קבצים מתאימים, וכך חוסך מקום בשאר הזמן:

```markdown title=".claude/rules/components.md"
---
paths:
  - "components/**/*.tsx"
---

# כללים לרכיבים
- כל רכיב בקובץ משלו, ושם הקובץ זהה לשם הרכיב (RecipeCard.tsx).
- כפתורים תמיד עם טקסט, לא רק אייקון.
- גודל טקסט מינימלי: 18 פיקסלים.
- טקסט שמוצג למשתמש: בעברית, ובלי לחבר עברית ואנגלית באותה מחרוזת.
```

```markdown title=".claude/rules/recipes-data.md"
---
paths:
  - "lib/recipes.ts"
  - "data/**"
---

# כללים לנתוני מתכונים
- לכל מצרך: כמות (מספר), יחידה ושם, בשדות נפרדים.
- אל תמחק מתכונים קיימים. אם צריך, תשאל.
```

### כלל 3: ייבוא קבצים עם `@`

במקום להעתיק מסמכים לתוך CLAUDE.md, מפנים אליהם. Claude Code טוען אותם יחד עם CLAUDE.md:

```markdown title="CLAUDE.md"
# אתר המתכונים של משפחת כהן

## חומרי רקע
@sources/references.md
@docs/design-guidelines.md
```

<Callout type="info" title="ייבוא לא חוסך מקום">
קבצים מיובאים נטענים בתחילת כל שיחה, בדיוק כמו CLAUDE.md עצמו. ייבוא עוזר **לסדר**, לא **לקצר**. כלל שרלוונטי רק לחלק מהקבצים עדיף לשים ב-`.claude/rules/` עם `paths`.
</Callout>

### כלל 4: הוראות לסיכום

כש-Claude Code מסכם שיחה, עם `/compact` או אוטומטית, חלק מהפרטים הולכים לאיבוד. אפשר להגיד לו מראש מה חשוב לשמור:

```markdown title="CLAUDE.md"
# הוראות לסיכום
כשאתה מסכם את השיחה, תמיד תשמור:
- את רשימת כל הקבצים ששינינו
- את הפקודות לבדיקה (npm run build וכל בדיקה אחרת שהרצנו)
- כל באג שעדיין לא נפתר
```

### כלל 5: הדגשה, במשורה

אם Claude מפספס שוב ושוב כלל אחד חשוב, אפשר להדגיש **אותו בלבד**:

```markdown title="CLAUDE.md"
- IMPORTANT: אל תמחק קבצים מהתיקייה data בלי אישור מפורש.
```

אם תדגישו עשרה כללים, אף אחד מהם לא יבלוט. ואם Claude מפספס הרבה כללים, הבעיה כנראה בגודל הקובץ: הוא ארוך מדי, והכללים החשובים הולכים לאיבוד.

### כלל 6: תהליכים ארוכים הם Skills, לא כללים

CLAUDE.md נטען **תמיד**. תהליך של עשרה צעדים שאתם צריכים פעם בשבוע, כמו "להוסיף מתכון חדש", תופס מקום בכל שיחה, גם כשלא צריך אותו. בשביל זה יש **Skills** (מיומנויות): הוראות שנטענות רק כשצריך אותן.

```markdown title=".claude/skills/new-recipe/SKILL.md"
---
name: new-recipe
description: הוספת מתכון חדש לאתר מתוך טקסט חופשי או תמונה של מתכון
---

1. תפרק את המתכון לשם, קטגוריה, זמן הכנה, מנות, מצרכים (כמות, יחידה, שם) ושלבים.
2. תציג לי את המתכון המפורק ותחכה לאישור.
3. תוסיף אותו ל-lib/recipes.ts, עם slug באנגלית.
4. תריץ npm run build ותוודא שעובר.
5. תשמור ב-git עם ההודעה "Add recipe: <שם המתכון באנגלית>".
```

עכשיו, בכל פעם שתדביקו מתכון ותכתבו "תוסיף את המתכון הזה", Claude יזהה שהמיומנות רלוונטית ויפעל לפיה. אפשר גם להפעיל אותה ישירות: `/new-recipe`. בפרק 11 נצלול לעומק ל-Skills: פרמטרים, הזרקת מידע חי, הרשאות ו-Skills מהקהילה.

### כלל 7: תחזוקה שוטפת

- **`/memory`**: פותח את קובצי CLAUDE.md לעריכה, ומראה גם את ה**זיכרון האוטומטי**: הערות ש-Claude שומר לעצמו מהתיקונים וההעדפות שלכם.
- **`/doctor prompt-audit`**: Claude עובר על כל קובצי ההוראות ומחפש כללים מיושנים, סתירות והפניות לקבצים שכבר לא קיימים. הוא מציג ממצאים ולא משנה כלום עד שתבקשו.
- **מבחן השורה**: על כל שורה שאלו, "אם אמחק אותה, Claude יטעה?". אם לא, מחקו. ההמלצה הרשמית היא פחות מ-200 שורות.

## חלק 3: MCP, לחבר את Claude לעולם

### מה זה MCP?

**MCP** (Model Context Protocol) הוא תקן פתוח שמאפשר לחבר את Claude Code לכלים ולמקורות מידע חיצוניים: Notion, Google Drive, מסדי נתונים, מערכות ניהול משימות ועוד. תחשבו על זה כמו על **שקע USB-C** לבינה מלאכותית: חיבור אחד סטנדרטי, שאליו אפשר לחבר המון כלים שונים.

כל כלי כזה נקרא **שרת MCP** (MCP Server). אחרי שמחברים שרת, Claude יכול להשתמש בו בשיחה, למשל לקרוא דף מ-Notion או לשאול שאלה את מסד הנתונים.

### לפני שמחברים: אולי לא צריך

<Callout type="tip" title="כלי שורת פקודה קודמים ל-MCP">
אם לשירות יש כלי שורת פקודה, כמו `gh` של GitHub (פרק 8) או `vercel` (פרק 9), עדיף בדרך כלל להשתמש בו. Claude יודע להפעיל אותם ישירות, והם חסכוניים יותר בהקשר. MCP מצוין לשירותים שאין להם כלי כזה, או כשרוצים חיבור עשיר יותר.
</Callout>

### מחברים שרת: דוגמה עם Notion

נניח שסבתא כתבה את כל המתכונים שלה בדף ב-Notion. במקום להעתיק אותם אחד אחד, נחבר את Claude ל-Notion.

**1. מוסיפים את השרת**, בטרמינל רגיל:

```bash title="בטרמינל"
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

**2. מתחברים.** בתוך Claude Code הריצו `/mcp`, בחרו את `notion`, ועקבו אחרי ההוראות בדפדפן כדי לאשר גישה:

```text title="בתוך Claude Code"
/mcp
```

**3. משתמשים:**

<Prompt>תקרא את הדף ״המתכונים של סבתא״ ב-Notion, ותוסיף כל מתכון שמופיע שם ועוד לא קיים אצלנו ל-lib/recipes.ts, לפי הכללים ב-CLAUDE.md. לפני ההוספה תציג לי רשימה של מה שמצאת</Prompt>

| --- | --- | --- |
| **מרוחק** (HTTP): שירות בענן | `claude mcp add --transport http <שם> <כתובת>` | Notion, Sentry, GitHub |
| **מקומי** (stdio): תוכנה שרצה אצלכם | `claude mcp add <שם> -- <פקודה>` | חיבור למסד נתונים מקומי |

בשרת מקומי, כל מה שאחרי `--` הוא הפקודה שמפעילה את השרת. משתני סביבה, כמו מפתחות, מעבירים עם `--env`:

```bash title="שרת מקומי עם מפתח (דוגמה)"
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable -- npx -y airtable-mcp-server
```

### ניהול שרתים

```bash title="בטרמינל"
claude mcp list            # כל השרתים, והאם הם מחוברים
claude mcp get notion      # פרטים על שרת אחד
claude mcp remove notion   # הסרת שרת
```

### היקף: למי השרת זמין?

| היקף | הדגל | למי | איפה נשמר |
| --- | --- | --- | --- |
| **מקומי** (ברירת מחדל) | `--scope local` | רק אתם, רק בפרויקט הזה | בהגדרות האישיות שלכם |
| **פרויקט** | `--scope project` | כל מי שעובד על הפרויקט | `.mcp.json` בשורש הפרויקט, ונשמר ב-Git |
| **משתמש** | `--scope user` | רק אתם, בכל הפרויקטים | בהגדרות האישיות שלכם |

<Callout type="warning" title="בטיחות MCP: לחבר רק מה שסומכים עליו">
- **רק שרתים ממקור מוכר.** שרת MCP מקבל גישה לכלים ולמידע שלכם. שרת לא מוכר הוא כמו תוכנה לא מוכרת.
- **הזרקת הוראות** (Prompt Injection): שרת שמביא תוכן מבחוץ, כמו דפי אינטרנט, מיילים או מסמכים, עלול להביא גם טקסט שמנסה "לתת הוראות" ל-Claude. היו ערניים לפעולות שלא ביקשתם.
- **הרשאות מינימליות.** חיבור למסד נתונים? משתמש לקריאה בלבד. מפתח API? רק עם ההרשאות שבאמת צריך.
- **מפתחות לא נכנסים ל-`.mcp.json`** שנשמר ב-Git. השתמשו בהיקף מקומי, או במשתני סביבה.
- **שרתים שלא בשימוש, מכבים.** כל שרת מחובר תופס מקום בהקשר. ב-`/mcp` אפשר לראות ולכבות.
</Callout>

### הפרויקט הבא: מסד נתונים לאתר המתכונים

זוכרים את טופס הוספת המתכון מפרק 6, שעבד רק על המחשב? השדרוג הטבעי הוא **מסד נתונים אמיתי**, כך שכל המשפחה תוכל להוסיף מתכונים ישירות מהאתר שבאוויר. זה פרויקט מצוין לתרגל בו את כל מה שלמדתם: תכנון, ענף, בנייה בשכבות, סקירה, ו-Preview ב-Vercel לפני מיזוג.

<Prompt>/plan אני רוצה שהמתכונים באתר יישמרו במסד נתונים אמיתי במקום בקובץ, כך שטופס ההוספה יעבוד גם באתר שבאוויר ב-Vercel. תציע שתיים-שלוש אפשרויות למסד נתונים שמתחבר בקלות ל-Vercel ומתאים לפרויקט קטן, עם יתרונות וחסרונות ועלויות בשפה פשוטה. אחרי שאבחר, תכין תוכנית בשלבים קטנים: כל שלב בענף משלו, עם דרך לבדוק אותו</Prompt>

### עוד רעיונות לפרויקטים

- **דף נחיתה** לעסק של מישהו מהמשפחה, עם טופס יצירת קשר.
- **אלבום תמונות משפחתי** עם חיפוש לפי שנה ואירוע.
- **כלי קטן** שחוסך עבודה ידנית: סידור קבצים, איחוד טבלאות, שינוי שמות של תמונות.
- **תיק עבודות** אישי, עם הפרויקטים שבניתם בקורס.
