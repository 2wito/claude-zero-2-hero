# העלאת האתר לאוויר ב-Vercel

עד עכשיו האתר שלכם רץ רק על המחשב שלכם, ב-`localhost:3000`. בפרק הזה הוא יקבל כתובת אמיתית באינטרנט, שאפשר לשלוח לכל המשפחה בוואטסאפ.

נשתמש ב-**Vercel**, שירות אחסון שנבנה על ידי החברה שמפתחת את Next.js. החלק הכי יפה: אחרי חיבור חד-פעמי ל-GitHub, **כל דחיפה ל-main מעדכנת את האתר לבד**, בלי ללחוץ על שום כפתור.

<Callout type="note" title="מה תלמדו בפרק">
- לחבר את המאגר ב-GitHub ל-Vercel, ולקבל העלאות אוטומטיות.
- להגדיר משתני סביבה (Environment Variables) והגדרות בנייה.
- לחבר דומיין משלכם, כמו `grandma-recipes.co.il`.
- לבדוק את האתר באוויר, ולטפל בהעלאות שנכשלו.
</Callout>

<Callout type="info" title="מה צריך לפני שמתחילים">
- פרויקט Next.js שעובד, כמו אתר המתכונים מפרק 6.
- הפרויקט נמצא ב-**GitHub** (פרק 8).
- `npm run build` עובר במחשב בלי שגיאות (פרקים 6 ו-7).
</Callout>

## שלב 1: מחברים את GitHub ל-Vercel

### 1.1 פותחים חשבון

1. היכנסו ל-[vercel.com](https://vercel.com) ולחצו **Sign Up**.
2. בחרו בתוכנית **Hobby**, התוכנית החינמית.
3. בחרו **Continue with GitHub** והתחברו עם חשבון ה-GitHub שלכם. כך Vercel יוכל לגשת למאגרים שלכם.

<Callout type="info" title="Hobby או Pro?">
תוכנית **Hobby** חינמית ומתאימה לפרויקטים **אישיים ולא מסחריים**, כמו אתר מתכונים משפחתי. אם האתר משמש לעסק, למשל אתר להזמנת עוגות שמוכרים, צריך את תוכנית **Pro** בתשלום. התנאים והמחירים המעודכנים נמצאים ב-[vercel.com/pricing](https://vercel.com/pricing).
</Callout>

### 1.2 מייבאים את הפרויקט

1. בלוח הבקרה של Vercel, לחצו **Add New...** ← **Project**.
2. תחת **Import Git Repository** תופיע רשימת המאגרים שלכם מ-GitHub. מצאו את `grandma-recipes` ולחצו **Import**.
3. המאגר לא מופיע? לחצו על הקישור להגדרת הגישה ל-GitHub (בנוסח **Adjust GitHub App Permissions**), ובחלון של GitHub אשרו ל-Vercel גישה למאגר הזה.

<Callout type="tip" title="רק למאגרים שצריך">
כש-GitHub שואל לאילו מאגרים לתת ל-Vercel גישה, עדיף לבחור **Only select repositories** ולסמן רק את המאגרים שאתם מעלים, ולא את כולם. זה עיקרון בטיחות טוב: לתת לכל כלי רק את מה שהוא צריך.
</Callout>

### 1.3 מסך ההגדרות

אחרי ה-Import מופיע מסך **Configure Project**. ברוב הפרויקטים לא צריך לשנות בו כלום:

| --- | --- | --- |

## שלב 2: משתני סביבה והגדרות בנייה

### מה זה משתני סביבה?

**משתני סביבה** (Environment Variables) הם הגדרות שהקוד צריך, אבל שלא שומרים בתוך הקוד עצמו. בעיקר מדובר בדברים סודיים, כמו מפתח API או סיסמה למסד נתונים, ובדברים ששונים בין סביבות, כמו כתובת האתר.

במחשב שלכם הם נמצאים בקובץ בשם `.env.local`, שלא עולה ל-GitHub, כי הוא ב-`.gitignore`:

```bash title=".env.local (במחשב שלכם בלבד)"
SITE_NAME="המתכונים של סבתא"
CONTACT_EMAIL="family@example.com"
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
```

כיוון שהקובץ הזה לא מגיע ל-GitHub, גם Vercel לא רואה אותו. לכן צריך להגדיר את המשתנים **גם ב-Vercel**.

### מוסיפים משתנים ב-Vercel

1. בלוח הבקרה של הפרויקט, לחצו **Settings** ← **Environment Variables**.
2. הזינו את שם המשתנה (**Key**) ואת הערך שלו (**Value**).
3. בחרו לאילו סביבות הוא שייך:
   - **Production**: האתר הראשי.
   - **Preview**: תצוגות מקדימות של ענפים ו-PR.
   - **Development**: למי שמושך את המשתנים למחשב עם כלי שורת הפקודה של Vercel.
4. לחצו **Save**.
5. **חשוב:** משתנים חדשים חלים רק על העלאות **חדשות**. כדי שהאתר הנוכחי יכיר אותם, היכנסו ל-**Deployments**, לחצו על שלוש הנקודות (**...**) ליד ההעלאה האחרונה, ובחרו **Redeploy**.

<Callout type="warning" title="NEXT_PUBLIC_ = גלוי לכולם">
ב-Next.js, משתנה ששמו מתחיל ב-`NEXT_PUBLIC_` נשלח **לדפדפן של כל גולש**, וכל אחד יכול לראות אותו. זה מתאים לדברים ציבוריים, כמו כתובת האתר. **לעולם אל תשימו מפתח API או סיסמה במשתנה שמתחיל ב-`NEXT_PUBLIC_`.** משתנים בלי התחילית הזאת זמינים רק בצד השרת, ונשארים סודיים.
</Callout>

Claude יכול לעזור לסדר את זה:

<Prompt>תעבור על הקוד ותיצור רשימה של כל משתני הסביבה שהפרויקט משתמש בהם. לכל משתנה: האם הוא סודי, האם הוא חייב להיות זמין בדפדפן (ולכן מתחיל ב-NEXT_PUBLIC_), ומה הערך שלו צריך להיות בייצור. תיצור גם קובץ .env.example עם השמות בלבד, בלי ערכים אמיתיים, כדי שיהיה תיעוד בפרויקט</Prompt>

<Callout type="note" title="מה זה .env.example?">
קובץ עם **שמות** המשתנים בלבד, בלי הערכים הסודיים. אותו כן שומרים ב-Git, כדי שמי שמוריד את הפרויקט, או אתם בעוד חצי שנה, ידע אילו משתנים צריך להגדיר.
</Callout>

### הגדרות בנייה

ברוב הפרויקטים Vercel מזהה הכול לבד. אם בכל זאת צריך לשנות, ההגדרות נמצאות ב-**Settings** ← **Build and Deployment** (בממשקים ישנים יותר: **General**):

| הגדרה | ברירת המחדל ב-Next.js | מתי לשנות |
| --- | --- | --- |
| **Build Command** | `npm run build` | אם יש לכם סקריפט בנייה מיוחד |
| **Install Command** | `npm install` (מזוהה לפי קובץ הנעילה) | כמעט אף פעם |
| **Output Directory** | מזוהה אוטומטית | כמעט אף פעם |
| **Root Directory** | `./` | אם הפרויקט בתת-תיקייה במאגר |
| **Node.js Version** | גרסה עדכנית שנתמכת | אם הבנייה נכשלת בגלל גרסה, כדאי שתתאים לגרסה במחשב שלכם (`node -v`) |

## שלב 3: דומיין משלכם

`grandma-recipes.vercel.app` עובד מצוין, אבל `grandma-recipes.co.il` נראה הרבה יותר טוב. הנה איך מחברים.

### 3.1 קונים דומיין

דומיין קונים אצל **רשם דומיינים** (Registrar). יש הרבה: חברות ישראליות שמוכרות סיומות `.co.il`, רשמים בינלאומיים לסיומות כמו `.com`, וגם Vercel עצמו מוכר דומיינים. מחיר שנתי של דומיין נע בדרך כלל בין עשרות למאות שקלים, תלוי בסיומת.

<Callout type="tip" title="הכי פשוט: לקנות דרך Vercel">
דומיין שנקנה דרך Vercel (בלשונית **Domains**) מתחבר לפרויקט אוטומטית, בלי שום הגדרות DNS. אם הדומיין נקנה במקום אחר, ממשיכים לשלב 3.2.
</Callout>

### 3.2 מוסיפים את הדומיין ב-Vercel

1. בפרויקט, היכנסו ל-**Settings** ← **Domains**.
2. לחצו **Add Domain**, הקלידו את הדומיין (למשל `grandma-recipes.co.il`) ולחצו **Add**.
3. Vercel ישאל איך לטפל בגרסה עם `www`. ההמלצה: להוסיף את שתיהן, ולהפנות אחת לשנייה, כך ששתי הכתובות יעבדו.
4. Vercel יציג **רשומות DNS** שצריך להגדיר אצל הרשם, עם סימן אזהרה עד שהן יוגדרו.

### 3.3 מגדירים DNS אצל הרשם

**DNS** הוא ה"ספר טלפונים" של האינטרנט: הוא אומר לדפדפנים לאן ללכת כשמישהו מקליד את הדומיין שלכם. צריך להוסיף אצל הרשם שתי רשומות, לפי מה ש-Vercel מציג:

| סוג רשומה | שם (Name / Host) | ערך (Value) | בשביל |
| --- | --- | --- | --- |
| **A** | `@` | כתובת IP ש-Vercel מציג, לרוב `76.76.21.21` | הדומיין הראשי: `grandma-recipes.co.il` |
| **CNAME** | `www` | כתובת ש-Vercel מציג, בנוסח `cname.vercel-dns.com` | הגרסה עם www |

<Callout type="warning" title="העתיקו את הערכים מ-Vercel, לא מכאן">
הערכים בטבלה הם דוגמה נפוצה, אבל Vercel עשוי להציג לפרויקט שלכם ערכים אחרים. תמיד העתיקו בדיוק את מה שמופיע במסך **Domains** של הפרויקט. ואם יש אצל הרשם רשומות **A** ישנות לאותו שם (למשל של "דף חניה" של הרשם), מחקו אותן, אחרת הן יתנגשו.
</Callout>

### 3.4 מחכים, ובודקים

- שינויי DNS לוקחים בדרך כלל **כמה דקות עד כמה שעות**, ובמקרים נדירים עד 48 שעות.
- כשהכול מוגדר נכון, הסימן ליד הדומיין ב-Vercel יהפוך ל-V ירוק (**Valid Configuration**).
- Vercel מנפיק **תעודת אבטחה (HTTPS)** לבד ובחינם. המנעול בשורת הכתובת יופיע בלי שתעשו כלום.

### האתר שבור באוויר? חוזרים אחורה בשנייה

לפעמים ההעלאה **מצליחה**, אבל משהו באתר לא עובד כמו שצריך. במקרה כזה לא צריך לחכות לתיקון:

1. היכנסו ל-**Deployments**.
2. מצאו את ההעלאה האחרונה שעבדה טוב.
3. לחצו על שלוש הנקודות (**...**) ובחרו **Instant Rollback** (או **Promote to Production**, תלוי בממשק ובתוכנית).

האתר יחזור לגרסה הקודמת תוך שניות. עכשיו אפשר לתקן בנחת, עם Claude, ולדחוף כשהתיקון מוכן ובדוק.

<Callout type="warning" title="חזרה ב-Vercel היא לא חזרה ב-Git">
Rollback ב-Vercel מחזיר את **האתר שבאוויר** לגרסה קודמת, אבל הקוד הבעייתי עדיין נמצא ב-main ב-GitHub. אם לא תתקנו אותו, הדחיפה הבאה תעלה אותו שוב. אחרי Rollback, תמיד: לתקן, או לבטל את השינוי עם `git revert` (פרק 7), ולדחוף.
</Callout>

## למתקדמים: Vercel מהטרמינל

ל-Vercel יש גם כלי שורת פקודה, שמאפשר ל-Claude לעבוד מול Vercel ישירות. הוא לא חובה, כי זרימת ה-Git שבנינו מספיקה, אבל הוא נוח למשתני סביבה ולבדיקת העלאות:

```bash title="התקנה והתחברות (בטרמינל רגיל)"
npm install -g vercel
vercel login
```

```bash title="פקודות שימושיות"
vercel link          # מקשר את התיקייה לפרויקט ב-Vercel
vercel env pull      # מוריד את משתני הסביבה לקובץ .env.local
vercel ls            # מציג את ההעלאות האחרונות
```

<Callout type="note" title="את ההתחברות עושים בעצמכם">
כמו `gh auth login` בפרק 8, גם `vercel login` הוא תהליך אינטראקטיבי שמתבצע בדפדפן. הריצו אותו בטרמינל רגיל. אחרי זה Claude יכול להשתמש בכלי.
</Callout>

## סיכום

- **חיבור חד-פעמי**: Vercel ← Import ← מאגר מ-GitHub ← Deploy. מאז, כל דחיפה ל-main מעדכנת את האתר, וכל ענף או PR מקבל כתובת Preview.
- **משתני סביבה** מגדירים ב-**Settings ← Environment Variables**, לסביבות הנכונות, ואחר כך עושים Redeploy. סודות אף פעם לא ב-`NEXT_PUBLIC_`.
- **דומיין**: **Settings ← Domains**, ואז רשומות DNS אצל הרשם בדיוק כמו ש-Vercel מציג. HTTPS מגיע לבד.
- **בדיקה באוויר**: רשימת בדיקה ידנית, Build Logs ו-Runtime Logs.
- **כשנכשל**: האתר הקודם נשאר באוויר. מעתיקים את השגיאה מ-Build Logs ל-Claude, ובודקים את החשודים הקבועים. כשהאתר באוויר שבור: Instant Rollback, ואז תיקון ב-Git.
