# Template Library: Ready-Made Agents, Commands and Skills

In chapters 11 and 12 we learned to build skills and agents ourselves. But you don't always need to start from scratch: the community has already written hundreds of them. This chapter is a **curated library**, with the most useful items from [aitmpl.com](https://www.aitmpl.com/), the catalog of the open-source project [Claude Code Templates](https://github.com/davila7/claude-code-templates) (MIT license).

Each item has an **explanation** of what it does and when to use it, an **install command** to copy, a **ready-made prompt** to run it, and a **sample result**.

<Callout type="note" title="How to use this chapter">
- **You don't need to install everything.** Start with 2 or 3 items that solve a problem you have right now.
- **Use the filter buttons** to see only agents, only commands, only skills or only utilities.
- **The sample results are illustrations.** The files in the catalog are written and updated by the community, so your results may look a bit different.
</Callout>

## Before you start

### What you need

- **Node.js** (chapter 6), since the install runs with `npx`.
- **A project with Git**, so you can see exactly which files the install added, and undo easily.
- Run the install commands **from inside the project folder**.

### How the install works

Each kind of component has its own flag:

```bash title="The general structure"
npx claude-code-templates@latest --agent   <category>/<name>  --yes
npx claude-code-templates@latest --command <category>/<name>  --yes
```

`--yes` skips the confirmation questions. And with no flag at all, you get an interactive selection screen:

```bash title="Interactive selection screen"
npx claude-code-templates@latest
```

<Callout type="warning" title="After every install: check what came in">
Every component from the catalog is **instructions Claude will carry out**, and sometimes tool permissions too. After installing:

1. Run `git status` to see which files were added. They're usually inside the `.claude` folder.
2. **Read the files**, or ask Claude to do it for you (the prompt is right below).
3. For agents, check the `tools` field. A "reviewer" agent asking for full write permissions should set off a red light.
4. Not a fit? `git restore` and `git clean` bring things back, or just delete the file.
</Callout>

<Prompt>I just installed components from claude-code-templates. Run git status, read every new file in the .claude folder, and explain to me what each one does, which tools it gets access to, and whether there's anything suspicious or unnecessary in it. Don't run any of them</Prompt>

<LibraryItem
  type="skill"
  title="Safe Refactoring (a skill you write yourself)"
  name=".claude/skills/refactor-safely"
  when="When you want every refactor in the project to go through the same safe process: tests first, small steps, a build after every step, and no behavior changes. This is a skill in the structure from chapter 11, ready to copy."
>

```markdown title=".claude/skills/refactor-safely/SKILL.md"
---
name: refactor-safely
description: Safely refactor a file or module without changing behavior. Use when the user asks to clean up, simplify, split, or restructure existing code.
argument-hint: [file-path]
---

Refactor $0 without changing any user-visible behavior.

1. Read $0 and list the problems (long functions, duplication, unclear names).
2. If there are no tests covering $0, write minimal tests that lock in
   current behavior FIRST, and run them.
3. Propose a plan of small steps. WAIT for approval.
4. Apply one step at a time. After each step run the tests and `npm run build`.
   If anything fails, revert that step and explain why.
5. Finish with a summary: what changed, what did not, and why it is safer.
```

```text title="Usage, inside Claude Code"
/refactor-safely components/RecipeCard.tsx
```

```text title="Sample result (illustration)"
Found 3 problems in RecipeCard.tsx. There were no tests, so 4 tests were written that lock in
the current behavior (4/4 passed). Plan: 3 steps. Waiting for approval.
```

</LibraryItem>

## Using installed components well

An installed component is only a starting point. Your prompt still determines the quality of the result:

<PromptCompare
  bad="Do a review"
  good="Use the code-reviewer agent on the changes in this branch against main. Focus on accessibility and mobile layout, since this is a family site for older users. Report by severity, with file and line, and without fixing."
  why="The strong prompt picks the agent explicitly, defines what to review and what to focus on, and sets the report format. The agent's general instructions connect to your specific context."
/>

<Callout type="tip" title="Adapt it to your project">
Community components are written in general terms. After installing, it's worth asking: "Adapt the code-reviewer agent to our project: add the rules from CLAUDE.md about accessibility and text size, and limit its tools to read only". That way you get the best of both worlds: a ready-made base, plus your rules.
</Callout>

## Summary

- **[aitmpl.com](https://www.aitmpl.com/)** is a catalog of agents, commands, skills and more, based on an MIT-licensed open-source project.
- **Installing**: `npx claude-code-templates@latest --agent ...` or `--command ...`, and with no flags you get a selection screen.
- **The recommended items**: code-reviewer, debugger, refactoring-specialist, documentation-engineer, test-automator and accessibility-tester, the commands create-pr, pr-review and commit, and a refactoring skill of your own.
- **Safety**: after every install, `git status`, read the files and check `tools`.
- **Adapting**: a community base, with your rules on top.
